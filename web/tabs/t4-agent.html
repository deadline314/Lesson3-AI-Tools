AI Agent — 自主代理人

2026 年最熱門的 AI 關鍵字就是 Agent。不同於傳統 Chatbot 只是「你問我答」，Agent 是能自主思考、規劃、行動、學習的程式。它會拆解目標、選擇工具、執行步驟、觀察結果，然後決定下一步——直到任務完成。

Agent 核心組件

🧠 Brain (LLM)

推理引擎——負責理解指令、分析情境、做出決策。模型的能力直接決定 Agent 的天花板。

💾 Memory

短期記憶（當前對話上下文）+ 長期記憶（跨 session 的知識庫）。讓 Agent 不會「金魚腦」。

🔧 Tools

外部能力接口——API 呼叫、網路搜尋、程式碼執行、資料庫查詢。Agent 透過工具與真實世界互動。

📋 Planning

策略分解——把大目標拆成可執行的小步驟。好的規劃能力讓 Agent 處理複雜任務。

🔄 Loop Controller

ReAct 循環管理器——控制 Think→Act→Observe 的迭代過程，決定何時繼續、何時停止。

規劃策略比較

A 理解問題 → B 收集資料 → C 分析 → D 輸出結果

適用：步驟明確、線性推理的任務。例如：數學題、簡單 debug。

問題
路徑 A 路徑 B 路徑 C
A1 ✗ B1 ✓ C1 ✗

適用：需要探索多條路徑、選擇最佳方案。例如：架構設計、創意發想。

Phase 1: 規劃

1. 定義目標
2. 列出步驟
3. 分配資源

Phase 2: 執行

→ 逐步執行
→ 檢查結果
→ 必要時重新規劃

適用：複雜多步驟任務、需要動態調整。例如：專案開發、研究報告。

Agent vs Chatbot

面向💬 Chatbot🤖 Agent
主動性被動回應主動規劃並執行
記憶僅當前對話短期 + 長期記憶
工具使用無或極少多工具協調
循環能力單次回應多次迭代直到完成
自主性低——需要人一步步引導高——給目標就能自己做
成本低（單次呼叫）高（多次 LLM + 工具呼叫）
風險低（只輸出文字）中高（會執行真實操作）

Agent 自主程度光譜

12345

Level 1：Tab 補全

產品範例：Copilot Autocomplete、Codeium

風險等級：🟢 極低——只建議，人決定是否採用

信任需求：不需要信任，每次都可檢視

Level 2：Cmd+K 指令

產品範例：Cursor Cmd+K、Copilot Chat inline

風險等級：🟡 低——修改可見範圍的程式碼

信任需求：低——改動在眼前，容易 review

Level 3：Composer / Chat

產品範例：Cursor Composer、Windsurf、Aider

風險等級：🟠 中——可跨檔案修改

信任需求：中——需要 review diff

Level 4：Agent

產品範例：Cursor Agent、Devin、Claude Code

風險等級：🔴 中高——自主執行多步驟、呼叫工具

信任需求：高——需要設定 guardrails 和審核機制

Level 5：Full Auto

產品範例：自動 CI/CD Agent、自動修 bug 機器人

風險等級：🔴 高——無人監督的持續運作

信任需求：極高——需要完整測試覆蓋 + 回滾機制

Hermes Agent 深入解析

Hermes 採用經典的 Agent 四層架構：

🧠 Brain

支援切換底層 LLM（GPT-4、Claude、本地模型），根據任務複雜度自動選擇。

💾 Memory

本地 SQLite 儲存對話歷史 + 向量資料庫儲存知識。跨 session 不遺忘。

🔧 Tools

可擴充的工具系統——自帶搜尋、計算、檔案操作，支援自定義工具。

🌐 Gateway

統一接入層——一個 Agent 同時服務 Discord、Slack、Web、Telegram。

傳統 chatbot 關掉視窗就失憶。Hermes 的記憶系統：

  • 對話記憶：自動摘要過去對話，存入本地 DB
  • 知識記憶：使用者教的事實、偏好、專案細節
  • 技能記憶：學會的操作模式，下次自動複用
  • 選擇性遺忘：可手動清除特定記憶

當 Agent 成功完成一個新類型的任務，它會：

1. 記錄完成步驟
2. 抽象成可重用的模板
3. 儲存為「技能」
4. 下次遇到類似任務直接調用

類似人類的「肌肉記憶」——第一次做要想，做過之後變成自動化。

測驗時間

Q1：你需要一個工具「每天自動爬取競品價格，存入資料庫，並在價格異常時發 Slack 通知」。應該用什麼？

💬 Chatbot——讓它每天回答一次就好
🤖 Agent——需要自主排程、多工具協調、循環執行
👥 Multi-Agent——一個 Agent 就夠了

Q2：使用者問「台北明天天氣如何？」且不需要後續動作。應該用什麼？

💬 Chatbot——單次問答，不需要記憶或工具循環
🤖 Agent——殺雞用牛刀，成本過高
👥 Multi-Agent——完全不需要

Q3：你想讓 AI 全自動處理：接收 GitHub issue → 分析需求 → 寫程式碼 → 跑測試 → 發 PR。該用什麼？

💬 Chatbot——無法自主執行多步驟
🤖 Agent——需要規劃、工具使用、循環驗證
👥 Multi-Agent——單一 Agent 足以處理
