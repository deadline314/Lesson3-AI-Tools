模型大地圖

工具是車殼，模型才是引擎。同樣是 Cursor，後面接 GPT-5 跟接 Claude Sonnet 4.6 的行為會差很多。在進入工具之前，先把 2026 年主流的模型梳理一遍——理解三個 Tier、模型個性、以及Reasoning Model 的運作方式。

三層模型光譜

TIER 1 · 旗艦
Claude Opus 4.7 GPT-5 Gemini 3 Ultra

最聰明、最貴、最慢

  • 價格：$10-75 / 1M tokens
  • 速度：30-80 tokens/sec
  • 適合：架構設計、複雜重構、困難 debug

什麼時候用旗艦？

只在「錯了代價很高」或「需要深度推理」時才動用。用得太頻繁會爆預算。把旗艦想成「諮詢資深顧問」——不是每天都需要，但關鍵時刻少不了。

場景：重新設計一個有 200+ API 的 legacy system 架構
為什麼用旗艦：需要同時考慮 backward compatibility、性能、維護成本
TIER 2 · 主力
Claude Sonnet 4.6 GPT-5 mini Gemini 3 Pro

平衡的日常戰馬

  • 價格：$2.5-15 / 1M tokens
  • 速度：60-120 tokens/sec
  • 適合：日常 coding、code review、一般任務

主力模型是你的預設選擇

80% 的工作都交給 Tier 2。它們夠聰明處理大部分任務，速度也不會讓你等到煩。只有遇到 Tier 2 解不好的問題，才升級到 Tier 1。

場景：寫一個 CRUD API + 單元測試
為什麼用主力：任務明確、不需要深度推理，主力模型綽綽有餘
TIER 3 · 高速
Claude Haiku 4.5 GPT-5 nano Gemini 3 Flash

便宜、快、堪用

  • 價格：$0.25-4 / 1M tokens
  • 速度：150-300 tokens/sec
  • 適合：autocomplete、分類、摘要、高頻呼叫

高頻低風險任務的首選

Tab 補全、文字分類、格式轉換——這些任務每天可能被呼叫幾千次，用旗艦會破產。Tier 3 用來處理「錯了也不會死」的高頻任務。

場景：IDE 中的即時 autocomplete
為什麼用高速：需要 <200ms 回應，而且一天觸發上千次
模型「個性」比較

每個模型家族都有獨特的行為風格，這些差異來自不同團隊的 RLHF 哲學：

特質ClaudeGPTGemini
回答風格謹慎、會澄清直接、自信結構化、條列
不確定時主動說「我不確定」傾向直接給答案給多個選項
Tool Use精準、不多做偶爾過度使用中規中矩
CodingAgent 任務最強生態系整合好超長檔案分析強
比喻謹慎的資深工程師自信的全端選手嚴謹的系統架構師
最適合Agentic coding通用對話大量文件分析

選模型像選隊友：寫 Agent 用 Claude 順、做日常對話用 GPT 順、做超長文件用 Gemini 順。

Input vs Output Token：為什麼價格不同？

幾乎所有 LLM API 都有這個差別：Output 比 Input 貴 3-5 倍。

模型Input ($/1M tokens)Output ($/1M tokens)比例
Claude Opus 4.7$15$755x
Claude Sonnet 4.6$3$155x
Claude Haiku 4.5$0.80$45x
GPT-5$10$303x
Gemini 3 Pro$2.50$104x

為什麼？Output 是一個一個 token 生成的，每個 token 都要重新走一次完整的 forward pass + 讀 KV cache。Input 是一次性 prefill，平行化效率高很多。所以 output 算力成本更高。

Prompt Caching：省 90% 的秘密武器

如果你的 system prompt 很長且會被重複呼叫，Prompt Caching 可以讓重複的部分只算 10% 的價錢。

100 次呼叫 5000 tokens system prompt：無 cache = $1.50，有 cache = $0.17。省 89%！

Batch API：非即時任務打 5 折

每晚整理 logs、生成週報這類不急的任務，用 Batch API 可以打 5 折，代價是要等最多 24 小時。

Cursor 的秘密武器：Composer 2 模型

Cursor 3 自己訓練了一個專用模型叫 Composer 2，只在 Cursor IDE 裡可用：

  • 速度：比 Sonnet 4.6 快 4 倍
  • 專精：針對 IDE 操作（跨檔編輯、重構、補全）優化
  • 限制：通用智能弱於旗艦模型，不適合做架構決策
  • 用法：在 Cursor 中預設就是 Composer 2，需要更強時手動切到 Claude/GPT

Composer 2 = 你的快速小幫手。遇到難題時升級到 Opus/GPT-5 = 請教資深顧問。

混合策略（推薦）

不要把整個 App 都用 reasoning model：

  • 主要對話流 → 普通 model（Sonnet 4.6 / GPT-5 mini）
  • 遇到困難子任務 → 呼叫一次 reasoning model（Opus 4.7 / o3）
  • 結果回到主流程繼續

就像你不會請諾貝爾獎得主幫你回 email——只在真正困難時才動用。
