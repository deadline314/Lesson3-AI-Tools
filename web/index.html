QUADRANT 01 · CODE

讓 AI 幫你寫程式

AI 編程工具分兩派：IDE 整合派（Cursor 為代表，活在編輯器裡） 和 CLI Agent 派（Claude Code 為代表，活在終端機裡，可以更主動）。 兩個工具不是互相取代，而是適合的場合不同。下面我們先看工具本體，再用情境題練習怎麼挑。

四個一定要懂的名詞

這四個名詞最近半年從圈內紅到圈外，它們不是行銷詞，是解決真實問題的設計。 點卡片展開細節，hover 任何元素看深層解釋。

MCP
Model Context Protocol
AI 跟外部世界的「通用插座」
USB-C 之於硬體，MCP 之於 AI——讓任何 AI 跟任何工具用同一套協定講話。 點擊展開 ↗

解決什麼問題

以前每個 AI 要連 Slack，都要為它寫一個 Slack 接口；連 Gmail 又要寫一個 Gmail 接口—— N 個 AI × M 個工具 = N×M 個接口，誰寫誰累。MCP 把這個統一成一套協定： 工具方提供一個 MCP Server，所有 AI 都能用同一套規則接上去。N+M 解法取代 N×M。

三層架構（hover 每層看）

HOST Claude Desktop / Cursor / Claude Code
↕ JSON-RPC 2.0 透過 stdio 或 HTTP/SSE
CLIENT Host 內負責跟 Server 溝通的模組
↕ 標準化請求
SERVER Slack / Notion / 自家資料庫 / GitHub ...

為什麼需要

LLM 知識很廣但不深。要它做你公司獨有的事——例如「用我們的格式寫週報」、「用我們的 SOP 做 code review」—— 丟在 system prompt 太亂、塞每次對話太貴。Skills 是把這些專業知識封裝成資料夾， AI 用到時自己去讀。標準從 Anthropic 開始，現在 Cursor / Codex / Gemini CLI 都跟進。

資料夾長這樣

my-skill/
├── SKILL.md# 入口 + 觸發條件
├── scripts/# 輔助腳本
├── references/# 詳細文件
├── assets/# 模板、範本
└── evals/# 測試用例

跟普通 LLM 的差異

普通 LLM：你問一句它答一句，回完就結束。
Agent：給它目標而不是問題，它會自己拆解、自己用工具、看結果不對再修正——會一直跑直到目標達成。 關鍵差別是有 loop 和有工具。

核心循環：ReAct

Reasoning + Acting 的縮寫，2022 年提出，現在所有 Agent 框架的基礎。

while not goal_reached:
  thought = llm.reason(state)
  action = llm.choose_tool(thought)
  observation = execute(action)
  state.update(observation)

為什麼重要

它不是最聰明的 Agent，但它會學習。 用得越久，越懂你；用得越久，會的事越多。其他 Agent 每次重啟都是新生兒，Hermes 是真的有記憶有經驗的 Agent。 而且 MIT license，免費可商用。
